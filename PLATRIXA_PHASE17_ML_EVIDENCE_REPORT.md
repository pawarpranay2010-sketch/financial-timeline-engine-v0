## 1. Headline question

> *How often does the current Qwen+LoRA model correctly compose the complete
> semantic interpretation Platrixa actually needs?*

The metric designed to answer this is **whole-transaction (compositional)
accuracy** — a case counts as correct only when ALL required semantic fields
for that transaction are simultaneously correct. Field accuracy is reported
separately and is diagnostic only (§21 of the phase contract is tested:
high field averages cannot hide compositional failures).

## 2. Benchmark size and composition

**92 locked cases**, deterministic IDs in the `PB-` namespace:

| category | count | purpose |
|----------|------:|---------|
| core | 40 | canonical semantic coverage: PURCHASE/SALE/PAYMENT/RECEIPT/CAPITAL/EXPENSE/RETURN_IN/RETURN_OUT/SETTLEMENT/DRAWING × payment modes, parties, discounts, GST |
| counterfactual | 24 (12 pairs) | one-fact-controlled pairs measuring sensitivity + stability |
| adversarial | 20 | distractor entities/amounts, reordered clauses, negation, contradiction, missing party/amount/payment, minimal-wording typos, swapped direction, ambiguous wording |
| paraphrase | 8 | same semantics, different surface forms |

## 3. Dataset construction method (independence methodology)

- **Hand-authored for this phase** — NOT generated by the P4 training
  pipeline, the 1000-example specialist generator, or any existing
  generation code. A separate generation/source process by construction.
- **Locked:** version string + sha256 of the exact file bytes recorded here
  and asserted by the harness (`dataset_sha256()`); verified unchanged at
  Phase 17 closure (fresh `sha256sum` == harness value == this report).
- **Deterministic identifiers:** every case carries a unique `PB-XXXX` id;
  all IDs verified unique (fte_fyjc_68 §16).
- **Explicit train/eval separation:** the harness
  (`check_independence`) compares every benchmark ID and every
  normalized input text against **14** known training/eval corpora
  (the P4/P5A tiers, the 1000-example specialist splits, the 2026-08-28
  training exports, and the AI candidate cases). Any collision fails the run
  with `FAIL_INDEPENDENCE`.

**Overlap check evidence:** during authoring the check *caught* two
accidental collisions with training inputs (`Purchased goods from Raj for
Rs.20000 on credit` = C0004; `…by cheque` = C0008). Those cases were reworded
(Deshpande/Iyer) and the final dataset verifies clean against all corpora.
The detection capability itself is regression-tested with a planted
collision (fte_fyjc_68 §18).

## 4. Evaluation path (production semantics — nothing benchmark-only)

```
input text
  → adapter.interpret()                    (pluggable; production = LocalHFModelProvider)
  → candidate dict (18-field contract)
  → StructuredInterpretationValidator      → schema-validity metric (§14.I)
  → ExpandedGroundingGate.ground()         → grounding-compatibility metric (§14.J)
  → deterministic field comparison         → field metrics (§14.B–F)
  → ALL required fields correct            → whole-transaction verdict (§15)
```

The adapter protocol is the production provider itself for real runs;
a `DeterministicTestAdapter` (explicitly labeled as metric-plumbing-only)
exists so the metric layer is testable without a model.

## 5. Metrics implemented

- **Whole-transaction (compositional) accuracy** — headline.
- **Field accuracy** — transaction_type / parties / amounts / payment_method /
  ambiguities, each with deterministic comparators (Decimal-normalized
  amounts, set-based parties/ambiguities).
- **Counterfactual sensitivity** — did the interpretation change exactly in
  the pair's declared `expect_change` fields?
- **Unrelated-field stability** — did it stay equal in `expect_stable`?
- **Schema validity rate**, **grounding compatibility rate**,
  **category breakdown**, **latency**, **error taxonomy** (per-case errors,
  schema errors, grounding issues recorded in
  `training/phase17_benchmark_results.jsonl`).

Adversarial categories map to §16 of the phase contract: distractor entities,
distractor amounts, reordered clauses, missing counterparty/amount/payment,
negation, contradiction, irrelevant numerics, minimal wording changes,
swapped transaction direction, ambiguous wording.

## 6. Methodology verification (all proven by fte_fyjc_68, 51/51)

- dataset lock, ID uniqueness, version, hash (§16–17)
- independence check works — clean dataset passes, planted collision fails
  (§18)
- whole-transaction metric deterministic across runs (§19)
- counterfactual pair integrity: every pair's ground truths differ EXACTLY
  in its declared `expect_change` fields (12/12 after correcting two
  mis-declared pairs, CF-09/CF-12) (§20)
- field accuracy provably cannot substitute for compositional accuracy —
  an adapter that gets 4/5 fields right on every case but the type wrong
  scores high field-average and near-zero whole-transaction (§21)

## 7. Counterfactual pair design (12 pairs, §17)

Each pair isolates ONE semantic fact: payment mode (CF-01/06/11), transaction
direction (CF-02/05/07/09/12), counterparty identity (CF-03), amount
(CF-04/08/10), discount-vs-none (CF-10), capital-vs-loan (CF-09). Ground
truths for each member are locked independently.

## 8. Baseline evaluation — STATUS: BLOCKED (infrastructure)

The production adapter (`--adapter production`) runs the exact pinned
artifacts (`Qwen/Qwen2.5-1.5B-Instruct` @ `989aa798…`, LoRA
`Pranay-20/platrixa-fyjc-specialist-v0.1` @ `b5c0a37c…` — both present in
the local HF cache). Observed in this environment:

- weights load (338/338 shards), then generation **hangs and is killed by
  the OOM controller**;
- environment: **2.0 GB RAM, no swap** — Qwen2.5-1.5B fp16 weights alone are
  ~3.1 GB, plus tokenizer/KV/activations, so real inference is physically
  impossible here (confirmed by `free -g`, dmesg OOM signature);
- disk was simultaneously at 100% (34 MB free), excluding a CPU-quantized
  workaround.

Per the phase contract (§2/§22 discipline) the run was **not** retried,
faked, sampled, or substituted: **no model-quality numbers are reported.**
The harness design records such an outcome as `INFRASTRUCTURE_BLOCKED` with
per-case error records — never as model failure.

**Consequence:** whole-transaction accuracy, adversarial accuracy,
counterfactual sensitivity/stability, and latency **for the Qwen+LoRA
baseline are NOT measurable in this environment**. The 53-case P5A results
remain what they were: smoke/regression evidence only — and by this phase's
own standard, insufficient proof of model quality.

## 10. What this phase establishes (and does not)

- transaction-level (compositional) correctness as the headline metric,
  with field metrics demoted to diagnostics;

  sensitivity/stability;

- any conclusion about reasoning-depth vs data-coverage bottlenecks. Per
  §18, no architecture change is proposed — the benchmark must run first

  of a successor report with real numbers).

## 11. Limitations

- The benchmark measures SEMANTIC INTERPRETATION, not accounting reasoning —
  no general-intelligence or accounting-authority claims are made or
  supportable from it.
- Ground truth was authored by deterministic conventions (canonical enum
  forms, `NONE` ambiguity); a model with different-but-defensible
  normalization could be marked wrong on surface forms (comparators
  normalize case/amount format, not meaning).
- 92 cases is a large improvement over 53 but still modest; the harness and
  lock make enlargement safe (append with new PB- ids, re-pin the hash).
- Latency numbers are only meaningful on the hardware that runs the model.
